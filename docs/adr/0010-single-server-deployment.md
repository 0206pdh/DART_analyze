# ADR-0010: 단일 소형 서버에 웹·API·SQLite를 배포한다

- 상태: 채택
- 날짜: 2026-09-04

## 맥락

초기 사용량은 불명확하고 비용을 최소화해야 한다. 현재 프런트는 정적 파일이며 백엔드는 FastAPI다. SQLite는 애플리케이션과 같은 호스트의 영구 디스크가 필요하다.

## 판단 기준

- 최소 월 고정비
- 서울 사용자 지연시간
- 영구 디스크와 백업 가능성
- HTTPS와 배포 난이도
- 공급자 이동 가능성

## 비교

| 후보 | 예상 비용 구조 | 장점 | 단점 | 평가 |
|---|---|---|---|---|
| 소형 VPS/Lightsail 단일 서버 | 약 US$5~7/월부터 | 예측 가능한 비용, 영구 SSD, SQLite 적합 | OS 패치·백업·장애복구 직접 운영 | 채택 |
| PaaS 웹서비스 + 관리형 DB | 서비스별 고정비 | 배포와 로그가 편함 | 상시 인스턴스와 DB를 합치면 비용 증가 | 성장 후 후보 |
| 서버리스 함수 + 서버리스 DB | 사용량 기반 | 저사용량에 유리할 수 있음 | SQLite 사용 불가, 콜드스타트와 공급자 제약 | 보류 |
| Kubernetes | 높은 최소비용 | 대규모 다중 서비스 운영 | 현재 규모에 과도함 | 제외 |

## 결정

정적 프런트, FastAPI, SQLite를 하나의 Linux 서버에 배포한다. FastAPI가 정적 파일도 제공해 별도의 프런트 호스팅 비용과 CORS 구성을 없앤다. 시작 권장 사양은 1GB RAM급이며 실제 원문 파싱 메모리를 관측한다. 512MB는 가격은 낮지만 5~9MB 원문 복구 파싱과 배포 작업의 여유가 작다.

특정 사업자에 코드를 종속하지 않는다. 첫 후보로 서울 리전을 제공하고 가격이 예측 가능한 Lightsail 등을 비교한다. 2026-09-04 기준 공식 표의 공개 IPv4 Linux 번들은 0.5GB US$5/월, 1GB US$7/월부터지만 실제 리전 가용성과 세금은 생성 전에 다시 확인한다.

## 감수하는 단점

- 단일 장애 지점이다.
- 무중단 배포와 수평 확장이 어렵다.
- 패치, 방화벽, TLS, 백업 모니터링 책임이 사용자에게 있다.

## 재검토 조건

- 가용성 목표가 단일 서버 복구시간으로 충족되지 않음
- 1GB 메모리에서 OOM 또는 지속적인 swap 발생
- 다중 인스턴스가 필요해 SQLite 제약과 충돌
- 운영 부담이 관리형 서비스 추가 비용보다 커짐
