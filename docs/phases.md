# 단계별 개발 계획

각 단계는 다음 단계의 전제만 만든다. 기간은 팀 규모를 모르는 상태에서 고정하지 않고, 종료 조건으로 관리한다.

## Phase 0 — API와 원문 파싱 검증

상태: 완료 (2026-09-04)

목표: 가장 큰 기술 리스크인 DART 데이터 획득과 보고서 원문 구조를 코드 본격 개발 전에 확인한다.

- 인증키를 서버 환경변수에서 읽는 작은 검증 스크립트
- 회사 원장 다운로드와 회사명 검색 샘플
- 특정 회사의 최근 사업·반기·분기보고서 조회
- 원문 ZIP/XML에서 필요한 섹션 후보 추출
- 구조화 재무 API의 연결/개별, 분기 누적값 차이 확인
- 원본 응답 fixture를 비밀정보 제거 후 테스트 데이터로 저장

종료 조건: 대표 기업 5곳에서 회사 검색과 최신 보고서 선택이 되고, 원문 파싱 가능 범위와 실패 사례가 기록된다.

완료 결과: DART 클라이언트, 기업 원장 ZIP/XML 파서, 기업개황·공시목록·원문 다운로드 경계, 오류 매핑과 테스트를 구현했다. 실제 기업 원장 118,831개를 파싱했고 삼성전자, SK하이닉스, 현대자동차, NAVER, 카카오의 최신 정기보고서 원문 구조를 비교했다. 상세 결과는 [Phase 0 검증 결과](phase-0-findings.md)에 기록했다.

## Phase 1 — 기업·공시 탐색 MVP

상태: 완료 (2026-09-04)

목표: AI 없이도 기업을 찾고 최근 공시 근거를 탐색할 수 있다.

- 단일 웹 애플리케이션과 단일 관계형 DB
- 회사 원장 동기화 작업과 검색 자동완성
- 기업개황, 최근 정기공시, 원문 링크 화면
- 주요 재무 수치의 기간별 비교
- DART 응답 캐시, 오류 매핑, 관측 가능한 로그

종료 조건: 사용자가 회사명을 검색해 올바른 회사를 선택하고 최근 보고서·핵심 재무 변화를 확인한다.

완료 결과: SQLite/Alembic 데이터베이스, SQLAlchemy 회사 모델과 repository, 118,831개 기업 원장 upsert, 상장사 회사명·영문명·종목코드 검색, 기업개황·최근 정기공시 API와 화면을 구현했다. 접수번호 기준 원문 ZIP 캐시와 장 단위 텍스트 추출, DART 구조화 재무제표 기반 핵심 6개 지표 및 비교율까지 구현했다.

## Phase 2 — 채용공고와 근거 기반 분석

상태: 구현 완료, 실제 공고 평가 진행 예정 (2026-09-04)

목표: 채용 요구사항과 공시 근거를 연결한 자기소개서 방향을 만든다.

- 채용공고 본문, 지원 직무, 사용자 경험 입력
- 공고에서 역할·필수역량·우대역량·키워드 추출
- 공시에서 사업 방향·변화·리스크·투자 신호 추출
- 요구사항과 근거를 연결한 분석 생성
- 출처가 없는 기업 관련 문장을 차단하거나 명시적으로 “추론” 표시
- 분석 결과 저장과 재생성

종료 조건: 실제 공고 3~5개에서 모든 핵심 기업 주장에 출처가 있고, 사람이 연결 품질을 평가할 수 있다.

구현 결과: GPT-5.4 mini Responses API의 구조화 출력, 채용공고·직무·선택 경험 입력, 최신 공시 원문 자동 추출, 최대 40,000자 근거 선별, 사실/추론 구분, 허용된 출처 ID의 서버 검증, 결과·출처·입력 해시 저장, 웹 결과 화면을 구현했다. 삼성전자 샘플로 실제 호출해 11개 근거, 2개 직무 연결, 3개 작성 방향이 반환되는 것을 확인했다. 남은 종료 조건은 서로 다른 실제 공고 3~5개에 대한 사람의 품질 평가다.

## Phase 3 — 자기소개서 워크스페이스

목표: 분석을 사용자의 실제 경험과 문항별 글로 전환한다.

- 자기소개서 문항과 글자 수 입력
- STAR 경험 카드와 재사용 가능한 경험 보관
- 문항별 핵심 메시지, 개요, 초안 및 수정 제안
- 근거 패널과 사실/해석/사용자 경험의 시각적 구분
- 버전 기록, 내보내기, 개인정보 삭제

종료 조건: 사용자가 근거를 확인하면서 문항별 초안을 완성하고 이전 버전을 복구할 수 있다.

## Phase 4 — 검증된 확장

실사용 데이터로 필요성이 확인된 것만 추가한다.

- 허용되는 채용 사이트의 공식 API 또는 URL 가져오기
- 공시 동기화 백그라운드 작업 분리
- 보고서 검색 품질 개선(필요하면 전문검색/벡터 검색)
- 기업 비교, 알림, 협업 기능
- 부하나 독립 배포 필요가 실제로 생긴 모듈만 서비스로 분리

## 구현 순서 제안

다음 작업은 Phase 0 프로젝트 골격과 DART 스모크 테스트다. 기술 스택은 이 문서에서 성급하게 확정하지 않는다. 다만 MVP는 서버 렌더링/서버 API가 함께 있는 웹 프레임워크와 PostgreSQL 또는 개발 초기 SQLite 정도면 충분하다.
