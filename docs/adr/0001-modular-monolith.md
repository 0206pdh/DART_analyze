# ADR-0001: 모듈형 모놀리스로 시작한다

- 상태: 채택
- 날짜: 2026-09-04

## 맥락

초기 제품은 회사 검색, DART 수집, 보고서 분석, 생성, 사용자 문서 관리가 필요하다. 아직 트래픽, 팀 경계, 독립 배포 요구가 검증되지 않았다. 반면 DART 원문 파싱과 분석 품질이라는 제품 리스크가 크다.

## 판단 기준

- 한 명 또는 소규모 팀의 개발 속도
- 로컬 개발과 배포의 단순성
- 회사·공시·분석 데이터의 일관성
- 향후 고부하 작업만 분리할 수 있는가
- 초기 운영비와 장애 지점 수

## 비교

| 후보 | 장점 | 단점 | 현재 적합성 |
|---|---|---|---|
| 단순 모놀리스 | 가장 빠르게 시작 | 경계 없이 커지기 쉬움 | 보통 |
| 모듈형 모놀리스 | 단일 배포의 단순함과 코드 경계를 함께 확보 | 모듈 규칙을 팀이 지켜야 함 | 높음 |
| 마이크로서비스 | 독립 배포·확장·장애 격리 | 분산 트랜잭션, 네트워크 실패, 관측성, 배포 복잡도 | 낮음 |
| 서버리스 함수 집합 | 요청별 확장과 관리형 운영 | 콜드 스타트, 로컬 재현, 긴 파싱 작업과 상태 관리 복잡 | 낮음 |

## 결정

하나의 배포 단위와 하나의 관계형 데이터베이스를 사용하는 모듈형 모놀리스로 시작한다. 코드 내부 경계는 `companies`, `filings`, `jobs`, `analysis`, `documents`로 나누고, 모듈 간에는 공개된 애플리케이션 서비스만 호출한다.

긴 분석 작업은 같은 코드베이스의 작업 실행기에서 처리할 수 있지만 별도 마이크로서비스로 간주하지 않는다.

## 이유

- 초기 배포·로깅·인증·트랜잭션 복잡도를 낮춘다.
- 작은 팀이 데이터 모델과 사용자 흐름을 빠르게 바꿀 수 있다.
- 모듈 경계와 작업 인터페이스를 유지하면 나중에 필요한 부분만 분리할 수 있다.
- 현 단계에서 MSA는 네트워크 실패, 분산 추적, 데이터 일관성, 운영 비용을 추가하지만 해결할 확정 문제가 없다.

## 결과

- 모듈 내부 테이블을 다른 모듈이 임의로 수정하지 않는다.
- DART 클라이언트와 AI 공급자 클라이언트는 어댑터로 격리한다.
- 배치/작업 처리량이 웹 요청에 영향을 주면 작업 실행 프로세스부터 독립 확장한다.

## 감수하는 단점

- 한 배포의 장애가 전체 기능에 영향을 줄 수 있다.
- 모듈 간 DB 경계를 코드 리뷰와 테스트로 지켜야 한다.
- 일부만 다른 언어·런타임으로 운영하기 어렵다.

## 재검토 조건

다음 중 실제 지표로 확인될 때 관련 모듈 분리를 검토한다.

- 공시 수집/파싱 부하가 웹 응답 안정성을 반복적으로 해친다.
- 분석 작업에 별도의 확장·GPU·보안 경계가 필요하다.
- 여러 팀이 독립 릴리스 주기를 가져야 한다.
- 단일 DB가 측정된 병목이고 애플리케이션 수준 최적화로 해결되지 않는다.
