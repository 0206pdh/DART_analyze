# ADR-0005: HTTPX 기반 DART 어댑터를 사용한다

- 상태: 채택
- 날짜: 2026-09-04

## 맥락

DART API 호출에는 타임아웃, 연결 재사용, 테스트 대역, JSON과 ZIP 바이너리 처리가 필요하다. 외부 API 세부사항이 도메인 코드로 퍼지면 변경과 테스트가 어려워진다.

## 판단 기준

- 연결 풀과 명시적 타임아웃
- 동기/비동기 전환 가능성
- FastAPI 및 테스트 도구와의 궁합
- 외부 호출 없는 단위 테스트
- 의존성 무게

## 비교

| 후보 | 장점 | 단점 | 평가 |
|---|---|---|---|
| HTTPX | 동기/비동기 API, 연결 풀, MockTransport, FastAPI 테스트 생태계와 일관됨 | 외부 의존성 | 채택 |
| Requests | 단순하고 성숙함 | 비동기 클라이언트가 없고 테스트 도구를 추가 조합 | 보류 |
| urllib 표준 라이브러리 | 추가 의존성 없음 | 오류·타임아웃·모킹 코드가 장황함 | 제외 |
| aiohttp | 비동기 성능과 기능 풍부 | 동기 스크립트와 테스트에 별도 패턴 필요 | 보류 |

## 결정

DART 전용 `DartClient` 어댑터가 HTTPX 클라이언트를 소유하고 재사용한다. 모든 호출은 타임아웃을 가지며 DART의 HTTP 200 내부 상태 코드를 별도로 검사한다.

Phase 0은 CLI와 테스트 단순성을 위해 동기 클라이언트로 시작한다. 웹 요청 동시성이나 지연이 측정된 문제가 되면 인터페이스를 유지한 채 `AsyncClient`로 교체한다.

## 감수하는 단점

- 현재 동기 호출은 실행 중인 웹 워커를 점유한다.
- 클라이언트 생명주기를 닫지 않으면 연결 자원이 누수될 수 있다.

## 재검토 조건

동시 DART 호출 때문에 웹 요청 대기시간이나 워커 수가 병목이 되면 비동기 어댑터 또는 작업 큐로 전환한다.
