# ADR-0003: 생성 결과는 공시 근거에 연결한다

- 상태: 채택
- 날짜: 2026-09-04

## 맥락

기업 분석과 자기소개서 제안에 생성형 AI를 사용하면 모델이 그럴듯하지만 공시에 없는 전략이나 채용 의도를 만들어낼 수 있다. 사용자는 원문을 확인할 수 있어야 하며, 기업 사실과 작성 조언을 구별해야 한다.

## 결정

분석 입력은 선택한 공시 스냅샷과 사용자 입력으로 제한한다. 추출된 각 근거에 안정적인 source id를 부여하고 생성 결과가 기업 관련 사실을 말할 때 source id를 함께 반환하게 한다.

화면에서는 다음을 구분한다.

- 사실: 공시에서 직접 확인되는 내용과 출처
- 해석: 여러 사실에서 도출한 분석임을 표시
- 제안: 지원 직무·사용자 경험에 맞춘 작성 방향

출처가 없는 사실 문장은 검증 단계에서 제거하거나 근거 부족으로 표시한다. 접수번호, 보고서명, 접수일, 섹션명, 원문 링크를 분석 스냅샷에 보존한다.

## 판단 기준과 비교

| 후보 | 품질 | 검증 가능성 | 비용·복잡도 | 결정 |
|---|---|---|---|---|
| 모델 일반지식만 사용 | 최신성·정확성 불안정 | 낮음 | 낮음 | 제외 |
| 보고서 전체를 한 번에 입력 | 문맥 한계와 잡음 | 중간 | 높음 | 제외 |
| 섹션 추출 + source id 기반 생성 | 관련 문맥 집중 | 높음 | 중간 | 채택 |
| 모든 문서를 즉시 벡터 DB화 | 검색 확장성 높음 | 중간 | 초기 운영복잡도 높음 | 측정 후 검토 |

## 결과

- 모델 출력은 자유 텍스트만 받지 않고 구조화된 스키마로 검증한다.
- 최신 보고서가 바뀌어도 기존 결과가 어떤 자료를 사용했는지 재현 가능하다.
- “이 회사는 반드시 이 역량을 원한다” 같은 단정 대신 근거 수준을 표현한다.
- 출처 품질과 연결 정확도를 평가하는 fixture 기반 테스트가 필요하다.

## 초기에는 하지 않는 것

보고서 전체를 무조건 임베딩해 벡터 DB에 저장하지 않는다. 검증된 섹션 추출과 키워드/전문 검색으로 시작하고, 검색 누락이 측정될 때 임베딩 도입을 결정한다.

## 재검토 조건

섹션 기반 검색의 정답 근거 회수율이 목표에 미달하고, 임베딩 검색이 평가셋에서 유의미하게 개선될 때 혼합 검색을 검토한다.
