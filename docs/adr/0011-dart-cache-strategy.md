# ADR-0011: DART 데이터는 접수번호 기준으로 로컬 캐시한다

- 상태: 채택
- 날짜: 2026-09-04

## 맥락

DART 원문은 한 보고서가 약 5~9MB이고 외부 API에는 호출 제한과 점검 시간이 있다. 같은 접수번호의 원문은 제출 후 바뀌지 않으며, 정정은 새로운 접수번호로 제출된다. 초기 배포는 단일 서버와 SQLite를 사용한다.

## 판단 기준과 비교

| 후보 | 비용 | 응답속도·가용성 | 운영 복잡도 | 평가 |
|---|---:|---|---|---|
| 요청마다 DART 호출 | 저장비 없음 | 느리고 외부 장애·제한에 취약 | 낮음 | 제외 |
| 모든 공시 사전 다운로드 | 저장비와 동기화 부하 큼 | 빠름 | 매우 높음 | 제외 |
| 선택 기업 온디맨드 캐시 | 사용한 만큼 저장 | 반복 조회가 빠름 | 중간 | 채택 |
| 객체 스토리지 캐시 | 소액 사용량 비용 | 다중 서버에 적합 | 자격증명·수명주기 관리 필요 | 성장 후 후보 |

## 결정

회사 원장은 전체 동기화하고, 공시목록·기업개황·원문은 사용자가 요청한 기업만 가져온다. 공시 메타데이터와 추출 섹션은 SQLite에 저장한다. 원문 ZIP은 접수번호를 파일명으로 한 로컬 캐시 디렉터리에 저장하고 DB에는 경로·크기·해시·시각을 기록한다.

원문은 접수번호 기준 영구 캐시한다. 기업개황과 공시목록은 갱신 가능한 데이터이므로 명시적인 동기화 요청 또는 이후 TTL 정책을 사용한다.

## 감수하는 단점과 재검토

서버 디스크 백업에 원문 캐시가 포함되며 용량이 증가한다. 캐시가 5GB를 넘거나 다중 서버 배포가 필요하면 객체 스토리지로 이전한다.
