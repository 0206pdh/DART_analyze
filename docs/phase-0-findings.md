# Phase 0 검증 결과

검증일: 2026-09-04

## 결론

OpenDART 인증키, 기업 원장, 기업개황, 정기공시 목록, 원문 다운로드까지 실제 호출에 성공했다. 회사 검색용 전체 기업 원장은 메모리에서 정상 파싱할 수 있으며, 공시 원문은 선택한 기업에 한해 온디맨드로 내려받는 구조가 적합하다.

원문 파일은 `.xml`이지만 일부 본문에 이스케이프되지 않은 `&`가 있어 표준 strict XML 파서로는 읽히지 않았다. lxml 복구 모드에서는 5개 표본 모두 루트 `DOCUMENT`와 제목 구조를 복원했다. 결정과 비교는 [ADR-0007](adr/0007-recovering-dart-document-parser.md)에 기록했다.

## 기업 원장

- 전체 법인: 118,831개
- 종목코드가 있는 법인: 3,988개
- 확인 필드: `corp_code`, `corp_name`, `corp_eng_name`, `stock_code`, `modify_date`
- 검색 DB에는 전체 법인을 저장하되 상장 여부를 종목코드 유무로 필터링할 수 있다.

수치는 검증일에 내려받은 원장을 기준으로 하며 이후 변경될 수 있다.

## 공통 구조

5개 표본에서 다음 구조를 공통으로 확인했다.

- 보고서 표지 및 목차
- `I. 회사의 개요`
- `II. 사업의 내용`
- 재무 관련 장
- 감사, 이사회, 임직원 등 정기보고서 장
- DART 전용 `SECTION-*`, `TITLE`, `TABLE-GROUP`, `TABLE` 태그

Phase 1의 원문 추출기는 장/절 제목과 `ATOCID` 같은 원문 속성을 이용해 섹션을 분할하고, 표와 본문을 구분해야 한다.

## 발견한 실패·주의 사례

1. DART 공시검색은 날짜를 생략하면 당일 기준으로 조회되어 최근 공시가 없는 것처럼 보일 수 있다. 클라이언트 기본 범위를 최근 366일로 수정했다.
2. `013`은 공시목록에서 정상적인 빈 결과로 처리해야 한다.
3. 정정 보고서는 보고서명에 `[기재정정]` 등이 붙고 원문 앞부분에 정정 내역이 추가된다. 최신본을 사용하되 최초 제출과 정정 내용을 구분해야 한다.
4. XML 선언이 있어도 bare `&` 때문에 strict 파싱이 실패할 수 있다.
5. 보고서 한 건이 5~9MB 수준이어서 검색 요청마다 반복 다운로드·파싱하면 비효율적이다. 접수번호 기준 캐시가 필요하다.
6. 복구 파싱은 일부 손실 가능성이 있으므로 추출 문단에 접수번호와 장/절 식별자를 보존해야 한다.
