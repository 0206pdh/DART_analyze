# ADR-0012: 회사 검색은 관계형 DB 문자열 검색으로 시작한다

- 상태: 채택
- 날짜: 2026-09-04

## 맥락

회사 원장은 약 12만 건이며 검색 입력은 회사명 또는 6자리 종목코드다. 검색엔진을 추가하면 별도 서버 비용과 동기화 작업이 발생한다.

## 비교

| 후보 | 장점 | 단점 | 평가 |
|---|---|---|---|
| SQLite prefix/contains + index | 추가 비용 없음, 데이터 일관성 단순 | 중간 포함검색은 전체 스캔 가능 | 채택 |
| SQLite FTS5 | 빠른 전문검색 | 한국어 회사명 토큰화 이점이 작고 별도 가상 테이블 동기화 | 보류 |
| PostgreSQL trigram | 유사검색 품질과 인덱스 우수 | PostgreSQL 운영 필요 | 전환 후 후보 |
| Elasticsearch/Meilisearch | 강력한 오타·랭킹 | 별도 서비스 비용과 인덱스 운영 | 제외 |

## 결정

법인 표식과 공백을 제거한 `normalized_name`, 영문명의 공백·문장부호를 제거한 `normalized_eng_name`으로 정확일치, prefix, contains 순으로 정렬하고 종목코드 검색을 함께 지원한다. `씨앤`과 `씨엔`처럼 사용자가 혼용하기 쉬운 표기는 검색 키에서 정규화한다. `LG`와 `엘지`처럼 과거·현재 표기가 함께 존재하는 명확한 별칭도 검색한다.

전체 결과를 한 응답으로 보내지 않고 total/offset/limit 기반 페이지네이션을 사용한다. 기본 20개씩 반환하고 사용자가 목록을 스크롤하며 추가 조회한다.

제품 범위는 취업 지원 대상 기업 탐색에 집중하기 위해 `stock_code`가 존재하는 법인만 검색 결과에 노출한다. 전체 DART 원장은 동기화 검증과 향후 정책 변경을 위해 DB에 유지한다. 종목코드 존재 여부는 DART 원장 기준이며 현재 거래소 상장 상태와 완전히 같다고 단정하지 않는다.

## 재검토 조건

p95 검색이 150ms를 넘거나 실제 사용자 검색 실패가 평가셋의 5%를 넘으면 FTS5 또는 PostgreSQL trigram을 비교한다.
