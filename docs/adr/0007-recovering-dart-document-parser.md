# ADR-0007: DART 원문은 복구 모드 XML 파서로 읽는다

- 상태: 채택
- 날짜: 2026-09-04

## 맥락

OpenDART `document.xml`은 ZIP 안에 `.xml` 파일을 제공한다. 대표 기업 실데이터를 표준 라이브러리 `ElementTree`로 읽었을 때 본문 텍스트의 이스케이프되지 않은 `&` 등으로 strict XML 파싱이 실패했다. 파일은 수 MB 크기이며 DART 전용 태그와 표가 많다.

## 판단 기준

- 실제 DART 비정상 XML을 끝까지 읽을 수 있는가
- 태그와 속성 구조를 최대한 보존하는가
- XPath/스트리밍 등 향후 섹션 추출 기능
- 외부 엔티티와 네트워크 접근 차단
- 성능과 메모리 사용량

## 비교

| 후보 | 장점 | 단점 | 평가 |
|---|---|---|---|
| `xml.etree.ElementTree` strict | 표준 라이브러리, 의존성 없음 | 실제 원문의 bare `&`에서 전체 파싱 실패 | 회사 원장에만 유지 |
| 정규식으로 XML 선처리 후 strict 파싱 | 문제를 명시적으로 교정 가능 | 모든 문맥에서 안전한 치환이 어렵고 원문 변형 위험 | 제외 |
| BeautifulSoup/HTML 파서 | 깨진 마크업에 관대 | XML 태그·대소문자·구조 보존 예측성이 낮음 | 보류 |
| `lxml.etree.XMLParser(recover=True)` | 깨진 XML 복구, XPath, 큰 문서 지원, 보안 옵션 | 네이티브 의존성, 복구 중 일부 노드 손실 가능 | 채택 |

## 결정

회사 원장처럼 정상 XML은 표준 `ElementTree`로 처리한다. 공시 원문은 lxml의 XML 복구 모드를 사용하며 `no_network=True`, `resolve_entities=False`로 외부 엔티티와 네트워크 해석을 막는다. 대형 보고서를 위해 `huge_tree=True`를 사용한다.

원문 전체 보존과 파싱 결과를 구분한다. 파서가 복구한 트리만을 원본으로 간주하지 않으며, 분석 근거에는 원문 접수번호와 위치 메타데이터를 함께 남긴다.

## 감수하는 단점

- 복구 결과가 원래 의도와 다를 수 있어 섹션 추출 평가가 필요하다.
- lxml 바이너리 배포 호환성을 확인해야 한다.
- 매우 큰 트리는 메모리를 많이 사용하므로 Phase 1 이후 스트리밍 파싱을 검토한다.

## 재검토 조건

5개사 이상 평가에서 중요 섹션이 유실되거나 메모리 사용량이 운영 한도를 넘으면 토큰 단위 전처리 또는 스트리밍 파서로 대체한다.
