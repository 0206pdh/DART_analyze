# ADR-0018: 배포는 Supabase Postgres + Vercel 읽기 전용, 데이터는 상위 상장사 프리로드

- 상태: 채택
- 날짜: 2026-09-04
- 관계: ADR-0008(SQLite), ADR-0010(단일 서버), ADR-0011(온디맨드 캐시), ADR-0013(원문 파일 저장)의 재검토 조건이 발동한 결정

## 문제와 제약

첫 공개 배포를 해야 하고 고정비는 0에 가까워야 한다. ADR-0010이 미뤄 둔 "서버리스 + 서버리스 DB"를
실제 후보로 평가한다. 제약:

- 운영자는 개인이고 상시 서버·백업을 직접 운영하기 어렵다.
- 무료 구간을 쓴다: Supabase Postgres 500MB, Vercel Hobby 함수(실행 시간·크기 제한, 영구 디스크 없음).
- OpenDART는 일일 요청 한도가 있고 12만 개 전체 원문을 상시 수집할 수 없다.
- 사용자 대부분은 소수의 잘 알려진 상장사만 조회한다.

## 판단 기준

- 월 고정비
- 요청 경로에서 외부 I/O(DART 다운로드·파싱) 제거 가능성
- 무료 DB 용량 안에 수용 가능한 데이터 크기
- 배포·운영 난이도와 공급자 이동 가능성
- 콜드스타트와 함수 실행 시간

## 비교

| 후보 | 고정비 | 장점 | 단점 | 평가 |
|---|---|---|---|---|
| 단일 VPS + SQLite (ADR-0010) | US$5~7/월 | 영구 디스크, 온디맨드 캐시 그대로 | 상시 서버·백업 직접 운영, 개인 부담 | 보류 |
| Vercel + Supabase, 요청 시 DART 온디맨드 | 0 | 배포 간단 | 함수에 영구 FS 없음, 큰 원문 다운로드·파싱이 실행 시간 초과 위험 | 제외 |
| **Vercel + Supabase, 상위 상장사 프리로드 + 읽기 전용** | 0 | 요청 경로는 DB 읽기 + OpenAI 호출뿐, FS·타임아웃 문제 없음 | 프리로드 범위 밖 기업 미지원, 6개월 배치 운영 필요 | 채택 |
| 관리형 Postgres + 상시 PaaS 인스턴스 | 서비스별 고정비 | 온디맨드 유지, 확장 쉬움 | MVP에서 비용이 앞선다 | 성장 후 후보 |

## 결정

1. 운영 DB를 SQLite에서 Supabase Postgres로 옮긴다. 스키마·마이그레이션은 그대로 쓰고
   회사 원장 upsert에 Postgres `ON CONFLICT` 경로를 추가한다. 마이그레이션·배치는 직결(5432),
   서버리스 런타임은 트랜잭션 풀러(6543)로 접속한다.
2. `sync_companies.py`(회사 원장 12만 건, 검색용)와 신규 `preload_listed.py`(시가총액 상위
   N개 상장사의 프로필·최신 정기보고서 섹션·최근 2개년 연간 재무)를 6개월 주기로 로컬 또는 CI에서
   실행한다. 종목 목록은 OpenDART가 주지 않으므로 KRX 시가총액 데이터(FinanceDataReader 등)로 정한다.
3. 저장 섹션은 `회사의 개요`·`사업의 내용`·`경영진단`만, 섹션당 5만 자로 잘라 보관한다.
   재무제표 표(`재무에 관한 사항`)는 구조화 재무 API(ADR-0014)로 이미 수집하므로 원문 텍스트에서 제외한다.
   상위 1000개 기준 `filing_sections`는 압축 저장 후 수십 MB로, `companies`·`financial_metrics`와
   합쳐 500MB 안에 든다.
4. 배포 런타임은 `READ_ONLY=true`로 둔다. 이때 요청 시점 DART 폴백은 비활성화된다.
   `POST /api/companies/{corp}/refresh` 와 `.../financials/refresh` 는 프런트가 그대로
   호출하므로 403 대신 **저장된 데이터를 반환**한다(DART 호출 없음, 미프리로드 기업은 409).
   `POST /api/analyses` 도 미프리로드 기업에 409. 원문 재파싱이 필요한
   `POST /filings/{rcp}/extract` 만 403. `DART_API_KEY`는 배포 서버에 두지 않는다.
   DB 접속은 마이그레이션·배치는 Session pooler(5432), 서버리스 런타임은 Transaction
   pooler(6543)를 쓴다. Direct 연결(IPv6)은 배치 부하에서 연결이 끊긴다.
5. 원문 ZIP은 배포 환경에 저장하지 않는다(ADR-0013 재검토). 프리로드 시 `--store-archive`로
   로컬 보관만 선택할 수 있고, DB에는 메타데이터 행만 남긴다. 분석은 `filing_sections` 텍스트만 읽으므로
   ZIP 파일이 없어도 동작한다.

## 감수하는 단점

- 프리로드 범위 밖 기업은 조회·분석할 수 없다. 범위는 배치 재실행으로만 넓힌다.
- 데이터 신선도는 배치 주기(6개월)에 묶인다. 그 사이 신규 공시는 반영되지 않는다.
- Supabase 무료는 7일 무접속 시 일시정지되어 첫 요청이 느려질 수 있다(크론 핑으로 완화).
- Vercel Python 함수는 콜드스타트가 있고, 정적 파일 서빙·번들 크기 조정이 필요하다.
- OpenAI 호출은 여전히 요청 경로에서 동기 실행된다(ADR-0017). 함수 실행 시간 안에 드는지 관측해야 한다.
- 단일 무료 DB에 의존한다. 백업은 Supabase 제공 기능에 맡긴다.

## 재검토 조건

- 프리로드로 감당 안 되는 롱테일 조회 수요가 확인됨
- `filing_sections` 등으로 500MB에 근접함 → 유료 플랜 또는 범위 축소
- OpenAI 호출이 함수 실행 시간 한도를 반복적으로 초과 → 비동기 처리(ADR-0017 재검토)
- 신선도 요구가 6개월 배치로 충족되지 않음 → 증분 동기화 또는 온디맨드 부분 복원
- 상시 인스턴스 + 관리형 DB의 총비용이 운영 부담보다 낮아짐
