# ADR-0004: Python 3.13과 FastAPI를 백엔드로 사용한다

- 상태: 채택
- 날짜: 2026-09-04

## 맥락

백엔드는 OpenDART ZIP/XML 파싱, 향후 문서 정제와 한국어 텍스트 분석, HTTP API 제공을 담당한다. 현재 프런트는 정적 HTML/CSS/JavaScript이며 팀 규모는 작다.

## 판단 기준

- 문서·XML·AI 처리 생태계
- 타입과 API 입력/출력 검증
- 개발 속도와 테스트 용이성
- 향후 백그라운드 작업 재사용
- 초기 운영 복잡도

## 비교

| 후보 | 장점 | 단점 | 평가 |
|---|---|---|---|
| Python + FastAPI | 문서/AI 라이브러리 풍부, 타입 힌트 기반 검증·OpenAPI, 간결함 | CPU 병렬 처리와 패키징에 주의 | 채택 |
| TypeScript + NestJS | 프런트와 언어 통일, 강한 모듈 구조 | Phase 0에 보일러플레이트가 많고 Python 분석 도구 연계가 추가됨 | 보류 |
| TypeScript + Express/Fastify | 가볍고 생태계가 큼 | 검증·구조 규칙을 별도로 조합해야 함 | 보류 |
| Java + Spring Boot | 성숙한 운영·타입·대규모 팀 지원 | 현재 제품과 팀 규모에 초기 비용이 큼 | 제외 |
| Django | ORM·관리자·인증이 통합됨 | 아직 필요 없는 기능이 많고 API/분석 중심 MVP에 무거움 | 보류 |

## 결정

Python 3.13과 FastAPI를 사용한다. 애플리케이션은 FastAPI에 종속된 라우팅 계층과 순수 Python 도메인/어댑터 계층을 분리한다.

## 감수하는 단점

- CPU 집약 원문 파싱이 커지면 웹 프로세스와 작업 프로세스를 분리해야 한다.
- Python 런타임 타입만 믿지 않고 경계에서 스키마 검증과 테스트가 필요하다.
- 프런트와 타입을 자동 공유하지 않으므로 추후 OpenAPI 기반 클라이언트 생성을 검토한다.

## 재검토 조건

Python 런타임 자체가 측정된 병목이 되거나 조직의 주력 언어와 운영 표준이 달라질 때 재검토한다.
